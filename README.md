# Tillo Media — Telegram-бот вебинаров

Бот [@Tillojournal_bot](https://t.me/Tillojournal_bot) («Тилло Медиа бот»):
записывает людей на вебинары, собирает вопросы спикерам, показывает расписание
и сам напоминает записавшимся за день до вебинара.

---

## Для Аполлы — как этим пользоваться

### Добавить или изменить вебинар

Всё расписание и все тексты бота лежат в файле **[`bot.py`](bot.py)**, в самом
верху. Нажмите на файл, потом на карандаш (✏️) справа сверху, поменяйте что нужно
и нажмите зелёную кнопку **Commit changes**. Через пару минут бот обновится сам.

```python
WEBINARS = [
    {
        "date": "30.09.2026",          # дата строго так: ДД.ММ.ГГГГ
        "time": "19:00",
        "title": "Черепанова Екатерина: 5 ошибок...",
    },
]
```

Напоминания бот рассылает сам — заводить их отдельно не нужно. По умолчанию
он напоминает за 5, 3, 2 и 1 день до вебинара и ещё раз незадолго до начала.
Как это поменять и почему последнее напоминание требует отдельной настройки —
в разделе «Когда уходят напоминания» ниже.

**В один день можно поставить сколько угодно вебинаров** — просто добавьте ещё
блок с той же датой и другим временем. Бот считает их разными: у каждого свой
список записавшихся, своё напоминание и своя ссылка на зум. Время писать в
название не нужно, бот показывает его на кнопке сам.

Как только вебинар **начался**, бот перестаёт предлагать его в `/register` и
переносит в раздел «Уже прошли» в `/courses` — по времени начала, а не по
концу дня. Поэтому вечером 30 сентября записаться на утренний сеанс уже
нельзя, а на вечерний — ещё можно. Удалять прошедшие вебинары из расписания не
нужно: люди и их записи остаются, а рассылку им можно отправить и потом.

### Когда уходят напоминания

Настраивается в `bot.py` рядом с расписанием:

```python
REMINDER_DAYS = [5, 3, 2, 1]     # за сколько дней напомнить
REMINDER_BEFORE_START = True     # и ещё раз незадолго до начала
```

Уберите лишние числа, если сообщений получается слишком много: тот, кто
записался на все вебинары, получит по одному письму на каждое число из списка.

Напоминания «за столько-то дней» уходят сами: они привязаны к одному и тому же
времени суток, и будильник на него уже стоит.

Напоминание **перед началом** — исключение. Оно привязано ко времени каждого
вебинара, а бесплатный сервис засыпает без обращений, поэтому для него нужен
свой будильник. Если будильника нет, это напоминание просто не уйдёт, и
никакой ошибки вы не увидите.

**Если человек записался, когда все напоминания уже ушли** — например, за
полчаса до начала, — бот не оставит его без ссылки: сразу после регистрации
он пришлёт ему то же сообщение со ссылкой, что получили остальные. А ещё любой
записавшийся может попросить ссылку сам командой **`/link`** — бот покажет
только те вебинары, на которые записан именно он.

Это уже техническая часть, и в `/stats` её нет. Всё про будильники, часовые
пояса и служебные проверки показывает команда **`/health`** — она для
разработчика. Если в её ответе есть строка «⚠️ Проверка «перед началом» не
запущена», напоминание перед началом не уйдёт: перешлите этот ответ
разработчику.

### Изменить текст напоминания

В `bot.py` есть блок **`TEXT_REMINDERS`** — у каждого напоминания свой текст:
за 5 дней, за 3, за 2 и накануне (плюс отдельный текст перед самым началом).
Поэтому людям не приходит один и тот же текст каждый день.

Меняйте что угодно **внутри кавычек**. Бот сам подставит:

| В тексте | Что подставится |
|---|---|
| `{time}` | время вебинара: 11:00 |
| `{title}` | название вебинара из расписания |
| `{zoom}` | ссылка на зум **этого** сеанса |

«Через 5 дней», «уже завтра», дату и имя спикера пишите словами прямо в
тексте. Число перед текстом (`5:`, `3:` …) — за сколько дней до вебинара он
уходит: поменяли число — поменяйте и слова. Больше никаких слов в фигурных
скобках быть не должно.

Исключение — запасной текст `TEXT_REMINDER_DEFAULT` в конце блока. Он может
уйти в любой день, поэтому в нём стоит `{when}`, и бот сам подставит «через
5 дней» или «уже завтра». Оттуда `{when}` не удаляйте.

**Ссылка на зум** лежит в расписании, в поле `"zoom"` рядом с вебинаром —
у утреннего и вечернего сеанса она своя, поэтому и полей два. Пока поле
пустое, напоминание уйдёт без ссылки, а бот напишет об этом в группу.

⚠️ Тексты написаны под конкретный вебинар — в них словами вписаны дата и имя
спикера. **Перед следующим вебинаром обновите их**, бот этого не сделает.

### Изменить остальные тексты бота

Там же, ниже расписания, блок `TEXT_...`. Меняйте **только то, что внутри
кавычек**. `\n` — перенос строки, `\n\n` — пустая строка между абзацами.
Можно использовать `<b>жирный</b>`, `<i>курсив</i>`,
`<a href="ссылка">текст</a>`.

### Команды в рабочей группе

Напишите **`/help`** в группе «Вебинары Tillo» — бот покажет полную инструкцию
со всеми командами и примерами. Коротко:

| Команда | Что делает |
|---|---|
| `/stats` | сколько человек записано на каждый вебинар и когда уйдут напоминания |
| `/health` | техническая проверка — для разработчика, в обычной работе не нужна |
| `/broadcast ДД.ММ.ГГГГ ЧЧ:ММ текст` | разослать тем, кто записан на конкретный вебинар — **так шлите ссылки на зум** |
| `/broadcast ДД.ММ.ГГГГ все текст` | всем сеансам этого дня сразу, каждому одно сообщение — например, «спасибо» после вебинара (но не ссылки на зум: у каждого сеанса своя) |
| `/broadcast текст` | разослать всем записавшимся |
| `/dm текст` | написать лично — ответом (reply) на сообщение о регистрации или вопросе |
| `/check` | проверить напоминания вручную (обычно не нужно) |
| `/id` | показать номер чата (нужен только при настройке) |

### Кнопки и форматирование в рассылке

**Жирный, курсив и ссылку внутри слова** делайте прямо в поле ввода Телеграма,
как в обычном сообщении, — бот их сохранит. Раньше всё это терялось: бот читал
только голый текст.

**Кнопку со ссылкой** добавьте отдельной строкой в конце сообщения:

```
/broadcast 30.09.2026 все Спасибо, что были с нами! Дневник питания:
[Оплатить 1000 ₽](https://pay.cloudtips.ru/p/xxxxx)
[Оплатить 10 €](https://www.paypal.com/ncp/payment/xxxxx)
[Задать вопрос](https://t.me/AppolaAppola)
```

Каждая такая строка станет кнопкой под сообщением, а из текста исчезнет.
Кнопок можно до десяти, надпись — до 64 знаков, ссылка обязательно
с `https://`. Если строку не понять, бот откажется и ничего не отправит.

**Кнопкой становится строка, в которой только ссылка и больше ничего.**
Неважно, как эта ссылка сделана: написана как `[текст](адрес)` или наведена на
слова прямо в поле ввода. Телеграм на компьютере сам превращает `[текст](адрес)`
в ссылку, пока вы печатаете, — бот понимает и такой вид.

Та же ссылка в середине строки — это просто ссылка в слове:

```
Подробности [на странице курса](https://tillo.life/courses/xxx)
```

Надпись кнопки можно оформлять как угодно — бот возьмёт из неё только текст.

Кнопки умеет прикреплять **только бот** — из своей переписки так нельзя,
поэтому и не получалось.

**Любая рассылка `/broadcast` сначала показывается здесь, в группе, и уходит
только после кнопки «✅ Отправить».** Бот выкладывает ровно то, что получат
люди, пишет, кому и сколько человек, и спрашивает: **«✅ Отправить»** или
**«Отмена»**. Без нажатия никому ничего не уйдёт. Так и проверяйте: написали,
посмотрели, нажали «Отмена».

### Разослать картинку, кружок, голосовое, гифку или видео

1. Выложите это сюда, в группу «Вебинары Tillo» (можно переслать от спикера).
2. Ответьте на это сообщение (reply) командой, например
   `/broadcast 30.09.2026 11:00 Ждём вас сегодня!` — текст можно и не писать.
   Именно **ответом**: команда в подписи к самой картинке не сработает.
3. Бот покажет, что уйдёт, и спросит кнопками — как любую рассылку.

Картинка, гифка, видео и голосовое уходят вместе с текстом одним сообщением —
текст становится подписью. Кружок — двумя сообщениями, сначала кружок, потом
текст: у кружка подписи не бывает. Очень длинный текст (больше ~1000 знаков)
тоже уйдёт отдельным сообщением, следом.

Что стоит знать:

- Текст берётся **только из команды**. Подпись, которую вы поставили под самой
  картинкой в группе, людям не уйдёт.
- Альбом уходит целиком — про это ниже.
- Файлы, стикеры и опросы так разослать нельзя — бот откажется. Картинку или
  видео, отправленные «файлом», бот тоже видит как файл: выложите их заново
  как фото или видео.
- Кому — решают дата и время в команде, как в обычной рассылке: без даты —
  всем записавшимся, с датой и временем — одному сеансу (у утреннего и
  вечернего они отдельные).

### Кнопки в меню бота с готовым текстом

В меню бота (кнопка **Меню** слева от поля ввода) есть пункты «Курс
«Полезные привычки 2.0»» и «Дневник питания». Человек нажимает — и ему
сразу приходит готовый текст с кнопками: «Записаться на курс», «Оплатить».

**Поменять текст.** Откройте `bot.py`, найдите блок «КНОПКИ В МЕНЮ С ГОТОВЫМ
ТЕКСТОМ» — там `TEXT_COURSE` и `TEXT_DIARY`. Правьте прямо в них. Жирный —
`<b>так</b>`, ссылка в слове — `<a href="https://адрес">слово</a>`, перенос
строки — `\n`.

**Поменять кнопки.** Рядом с каждым текстом лежит свой список: `BUTTONS_COURSE`,
`BUTTONS_DIARY`. Строчка — это `("Надпись", "https://ссылка")`.

**Добавить ещё один пункт меню.** Напишите свой текст и список кнопок по
образцу, а потом добавьте строчку в список `INFO_PAGES` чуть ниже:

```
{"command": "podcast", "menu": "Подкаст",
 "text": lambda: TEXT_PODCAST, "buttons": lambda: BUTTONS_PODCAST},
```

`command` — латиницей, без пробелов (это то, что отправится боту), `menu` —
как пункт назовётся в меню. Чтобы убрать пункт из меню, удалите его строчку
отсюда. Новый пункт появляется у людей в меню после перезапуска бота — это
несколько минут после сохранения файла.

### Опрос

Варианты ответа напишите в конце рассылки — каждый отдельной строкой, в
квадратных скобках и **без ссылки**:

```
/broadcast 30.09.2026 все Спасибо, что были с нами!

Понравился вебинар?
[Да]
[Нет]
```

- Людям придёт сообщение с кнопками «Да» и «Нет». Кто нажмёт — увидит
  «Спасибо! Ваш ответ: Да», а кнопки у него исчезнут: ответить дважды нельзя.
- В эту группу придёт его ответ с именем и общим счётом:
  «📊 Понравился вебинар? — Анна: **Да**. Счёт: Да — 12 · Нет — 1». Подпись
  опроса — последняя строка текста перед вариантами, поэтому ставьте вопрос
  прямо над ними.
- Нужно хотя бы два варианта. Одна строка в скобках, например `[Важно]`,
  останется обычным текстом.
- **Один вопрос — одна рассылка.** Если в тексте два вопроса со своими
  вариантами, бот откажется: счёт был бы один на всех. Второй вопрос
  отправьте отдельной рассылкой. Несколько опросов одновременно — можно,
  у каждого свой счёт.
- Кнопки в предпросмотре здесь, в группе, настоящие, но ответы на них не
  считаются — бот так и скажет.
- Счёт хранится в закреплённом сообщении и не сбрасывается, даже если бот
  перезапустится. Бот ведёт его по последним 10 опросам; ответ на более
  старый всё равно придёт сюда, только без счёта.
- Кнопки со ссылками и альбом с опросом сочетаются так же, как обычно.

### Разослать альбом (несколько фото одним сообщением)

1. Выложите альбом сюда, в группу: от 2 до 10 фото или видео.
2. **Сразу** ответьте командой на любое фото альбома, как на обычную картинку.
3. Бот покажет весь альбом и спросит, отправлять ли.

- Подпись у альбома одна — это ваш текст из команды, если он короче ~1000 знаков.
- **Кнопок у альбома не бывает** — так устроен Телеграм. Если в команде есть
  кнопки, бот отправит альбом без подписи, а сразу следом — текст с кнопками.
  Поэтому с кнопками текст нужен обязательно, хотя бы пара слов.
- Альбом бот помнит, пока работает. Если между альбомом и командой он успел
  перезапуститься, он скажет «остальных фото не видел» и ничего не отправит —
  выложите альбом ещё раз и ответьте сразу.
- В предпросмотре пересчитайте фото: если какого-то не хватает, нажмите
  «Отмена» и отправьте команду ещё раз.
- Чтобы поправить текст после «Отмены», можно ответить командой и на копию
  альбома, которую бот показал в предпросмотре, — он её тоже помнит.

### Что делать после вебинара

**Убирать за собой не нужно — бот делает это сам:**

- сеанс пропадает из `/register` и `/stats`, как только начался;
- на следующий день его записи переезжают на лист «Архив» в `registry.xlsx`;
- отметки об уже отправленных напоминаниях бот стирает сам.

Никто из списка не пропадает: люди остаются и в файле, и в «Всего», и им
по-прежнему можно написать.

**Вебинары из расписания удалять не нужно.** Прошедшие показываются в
`/courses` в разделе «Уже прошли» — заодно видно, что уже было. Если когда-то
список станет слишком длинным, самые старые можно удалить, ничего не сломается:
рассылки, `/who` и файл со списком продолжат работать. Пропадут только две
вещи — вебинар исчезнет из «Уже прошли», и `/stats` перестанет напоминать про
«не привязанных» участников того дня, если они там были.

**По желанию, в тот же день или на следующий:**

```
/broadcast 30.09.2026 все Спасибо, что были с нами! Запись — по ссылке…
```

Уйдёт всем, кто записывался на этот день, каждому одно сообщение — даже если
человек был на обоих сеансах. Запись или материалы можно приложить картинкой,
видео или кружком: выложите их в группу и ответьте на них этой же командой.

**Перед следующим вебинаром — обязательно:**

1. Добавьте его в расписание и заполните `"zoom"` **у каждого сеанса** — у
   утреннего и вечернего ссылки разные.
2. **Перепишите тексты напоминаний** (`TEXT_REMINDERS`): в них словами вписаны
   дата и имя спикера, бот их не подставляет. Иначе люди получат приглашение на
   прошлый вебинар.
3. Успейте до **первого напоминания — оно уходит за 5 дней**. Для вебинара
   19.10.2026 это 14 октября.
4. Напишите `/stats` в группе и проверьте, что в ответе нет предупреждений
   (⚠️ про одинаковое время или про «не привязанных»).

### Как написать человеку лично

Нажмите на **имя** в сообщении «✅ Регистрация…» — откроется профиль, оттуда
можно написать. Если у человека закрыты личные сообщения, ответьте на то же
сообщение командой `/dm ваш текст` — тогда напишет бот.

### Список записавшихся — в Excel

Весь список лежит в рабочей группе в файле **`registry.xlsx`** — это последний
файл, который прислал бот (закреплённое сообщение указывает именно на него).
Скачайте его и откройте в Excel: по строке на каждую запись — кто, на какой
вебинар, @username и когда записался (по Москве). У тех, кто записался до
25.09.2026, время не указано — тогда бот его ещё не запоминал.

Последний столбец — **«статус»**. Там появляется «заблокировал(а) бота» у тех,
кому Телеграм больше не даёт писать. Таких людей бот **не удаляет**: они
остаются в списке и в «Всего», просто рассылки и напоминания их пропускают —
поэтому «не доставлено» в отчёте о рассылке из-за них не растёт. Сколько их —
показывает `/stats`. Если человек разблокирует бота и снова им воспользуется,
пометка снимется сама.

В файле два листа:

- **«Записи»** — на вебинары, которые ещё впереди;
- **«Архив»** — на те, что уже прошли.

Записи переезжают в «Архив» сами, когда вебинар прошёл. **Оттуда ничего не
пропадает и удалить оттуда нечем** — вместе это база всех, кто когда-либо
записывался, и рассылка `/broadcast` всем по-прежнему доходит и до тех, кто
в архиве.

Бот обновляет файл после каждой регистрации и держит в группе два последних,
старые удаляет сам. **Не удаляйте эти файлы и закреплённое сообщение** — из них
бот узнаёт, кто записан.

**И не закрепляйте в этой группе ничего другого.** Телеграм показывает боту
только последнее закреплённое сообщение: если закрепить поверх списка что-то
своё, бот список не увидит. Тогда он напишет об этом в группу и, пока
сообщение не открепят, не будет сохранять регистрации и отправлять
напоминания — чтобы не завести новый пустой список поверх старого.
Открепили — всё снова работает само.

## Для разработчиков

Весь бот — один файл `bot.py`. Это сознательное решение: владелец продукта
правит расписание и тексты через веб-интерфейс GitHub, без git и терминала.
Не разбивайте на модули.

### Стек

| | | |
|---|---|---|
| `python-telegram-bot` | `13.15` | API v13 (`Updater`, `use_context=True`). **Не** v20+ |
| Python | `3.11.9` (`.python-version`) | PTB 13 импортирует `imghdr`, удалённый в 3.13 |
| `urllib3` | `<2` | PTB 13 несовместим с urllib3 2.x |
| `setuptools` | `<81` | APScheduler в PTB 13 требует `pkg_resources` |

Файл зависимостей называется **`requirements`**, без `.txt` — Build Command на
Render задан как `pip install -r requirements`. Переименуете — почините и там.

### Запуск локально

```bash
python3.11 -m venv .venv && . .venv/bin/activate
pip install -r requirements
BOT_TOKEN=... ADMIN_CHAT_ID=-100... python bot.py
```

Без `RENDER_EXTERNAL_URL` бот поднимается в режиме polling — публичный URL для
локальной отладки не нужен.

### Хостинг

Render.com, free tier, сервис `Tillo-Bot-Web-1`; деплой автоматический из `main`.
Переменные окружения: `BOT_TOKEN`, `ADMIN_CHAT_ID` (отрицательный id рабочей
группы). `RENDER_EXTERNAL_URL` и `PORT` Render подставляет сам.

Free tier накладывает три ограничения, из которых следует вся архитектура:
диск не переживает перезапуск, сервис засыпает после ~15 минут без запросов,
и инстанс-часов хватает примерно на один сервис. Поэтому:

- **состояние хранится в самой рабочей группе**, а не на диске: список —
  в файле `registry.xlsx`, который бот присылает туда после каждой записи,
  а закреплённое сообщение указывает на этот файл;
- **используется webhook, а не polling** — спящий сервис будит входящий HTTP-запрос;
- **сервис будят внешние будильники** (cron на отдельном сервере) незадолго до
  времени рассылки; их часовой
  пояс обязан совпадать с `TIMEZONE` в `bot.py` (сейчас `Europe/Prague`).

Подробные технические заметки — причины решений, известные грабли, формат
хранилища и план развития — в `CLAUDE.md`.
